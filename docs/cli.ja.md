# lgfx-font-tool — CLI 仕様

[English](./cli.en.md)

- 状態: **v1 — 実装済み・テスト済み**（未決は §14）
- 対象読者: この CLI を実装する人・使う人
- 最終更新: 2026-08-28
- 本書の内容は `bin/` に実装があり、`test/cli.test.js` が終了コードと出力の契約を検査する

## 1. 位置づけ

**Web UI（Viewer / Generator / Converter / Inspector）と役割を分ける。**

Web UI は書体を探し、文字集合を組み立て、目で見て決めるための道具。CLI が引き受けるのは
**ブラウザに原理的にできないこと**だけにする。

| | Web UI | CLI |
| --- | --- | --- |
| 書体を探す・選ぶ | ○ | × |
| 文字集合を組み立てて眺める | ○ | × |
| 一度だけ変換して落とす | ○ | △ |
| **同じ操作を毎ビルド繰り返す** | × | **○** |
| **同じ結果を CI で再現する** | × | **○** |

### やらないこと

- **ソースコードの走査**（どの文字を使っているかの自動収集）— プロジェクト固有なので利用者側
- **git 操作** — CI の仕事
- **書体選び・文字集合の組み立て UI** — Web UI の仕事
- **凝った画像出力** — 画像は生成物ではなく**生成物の確認**（§8）

## 2. 設計の指針

1. **引数だけで完結する。** 設定ファイルを書かないと何も出ない道具にしない。
   単発利用が起点で、継続利用は「引数を保存したもの」にすぎない
2. **簡潔さを優先する。** ネットワークとローカルの資源は多少使ってよい。
   数 MB の取得やキャッシュより、**コマンドと概念の少なさ**を優先する
3. **出力結果が正。** 同じ環境で同じ入力なら同じバイト列が出る

### 継続利用は「同じコマンドの別モード」

| 使い方 | 形 |
| --- | --- |
| 単発 | `lgfx-font-tool build <引数>` |
| 日常の増減 | `npm run font`（= 保存した `build`） |
| CI 検証 | `npm run font -- --check` |

**設定ファイルは作らない。** 複数ターゲットは npm script の `&&` で足りる。
必要になれば「保存された引数」として後から互換に足せる。

## 3. コマンド

```
lgfx-font-tool build   [オプション]              フォントデータを作る（§4-§8）
lgfx-font-tool inspect <file> [オプション]       既存フォントを調べる（§9）
lgfx-font-tool charset <file> [オプション]       文字集合ファイルの正準化・一覧（§11）
```

3 つ。`build` が本体で、他の 2 つは補助。**`build` の指定はすべてオプション**で、
位置引数は取らない（入力・文字・出力の 3 種をフラグで組み合わせる）。

### 導入と版の確認・更新

インストールは要らない。`npx` が都度取ってくる。

```sh
npx lgfx-font-tool build ...   # 入れずに使う
npm i -D lgfx-font-tool        # プロジェクトに固定（CI ではこちら）
npm i -g lgfx-font-tool        # どこからでも lgfx-font-tool で呼ぶ
```

コマンド名とパッケージ名が同じなので、この 1 語が「取ってくるパッケージ」と「動かす
コマンド」の両方を指す。`-p` は要らない。インストール済みなら `npx` ごと省いて
`lgfx-font-tool build ...` でよい。

版の確認と更新。

```sh
lgfx-font-tool --version           # 動いているツールの版（-v / version も同じ）
npm ls lgfx-font-tool              # プロジェクトに入っている版
npm ls -g lgfx-font-tool           # グローバルに入っている版
npm view lgfx-font-tool version    # npm 上の最新（入っている版ではない）

npm i -D lgfx-font-tool@latest     # プロジェクトを最新に
npm i -g lgfx-font-tool@latest     # グローバルを最新に
npm i -D lgfx-font-tool@2.3.0      # 版を指定して固定
```

**`npx` の結果は同じマシンでも一定しない。** 原因は 3 つあり、上から順に効く
（3 つとも実測で確認）。

| | |
| --- | --- |
| PATH に同名のコマンドがあるとそれが勝つ | `npx lgfx-font-tool` はレジストリを見る前に名前でバイナリを見つけるので、`npm i -g` で入れた版が動く（実測: npx のキャッシュが古い版のままでもグローバルの 2.3.0 が動いた）。版を書くとその版込みの文字列を引くことになり、それに一致する bin は無いので、この経路には乗らない |
| cwd から上に `node_modules` があるとそれが勝つ | npx は `node_modules/.bin` を上へ探し、見つかれば取得もキャッシュも使わない。古い版を入れたディレクトリで実行すると、その版が動く |
| キャッシュは spec 文字列で引き、再解決しない | 版を書かない `npx lgfx-font-tool` は、その時点の最新を解決して `^x.y.z` として `~/.npm/_npx/<hash>/` に置く。次からは**その木をそのまま使う**ので、後で新しい版が出ても上がらない |

**書き方ごとの挙動**（npm 10.9.4 で実測）。

| | |
| --- | --- |
| `npx lgfx-font-tool` | 既にあるものが動く。PATH や `node_modules` に同名のコマンドがあればそれ、無ければ npx が最初にキャッシュしたもの。新しい版が出ても上がらず、**その旨も出ない** |
| `npx lgfx-font-tool@latest` | 版を引き直し、新しいものがあればインストールする。**聞かれるのはこのインストールのとき**で、端末なら `Ok to proceed?`、それ以外では `npm warn exec … will be installed` の 1 行だけ |
| `npx lgfx-font-tool@<版>` | 初回だけインストールし、以降はキャッシュから、問い合わせも確認もなく動く。**CI ではこれ**。`--pin-version` を付けたときに `Rebuild with` に書かれるのもこの形 |

**CI に `--yes` は要らない。** npm が聞くのは、stdin が TTY で**かつ** `ci-info` が CI だと
判定できなかったときだけ。GitHub Actions は `GITHUB_ACTIONS` を立てるので判定され、
stdin がパイプの場合も同じ黙って進む経路に入る。`--no` を書くと、その場面が質問ではなく
エラーになる。

実際に何が走ったかは `--version` で確かめるのが早い。

```sh
lgfx-font-tool --version              # まず実際に動くものの版を見る
which -a lgfx-font-tool               # PATH に何かあるか
ls node_modules/.bin/lgfx-font-tool   # cwd 側に何かあるか
npm ls -g --depth=0                   # グローバルに何が入っているか

npm i -g lgfx-font-tool@latest        # グローバルを上げる
npm rm -g lgfx-font-tool              # または消して npx に任せる
npx clear-npx-cache                   # キャッシュを捨てる
```

**確実にしたいならインストールする。** `npm i -D lgfx-font-tool` + `npm ci` なら
`package-lock.json` が版を決めるので、npx の解決順に左右されない。CI ではこちら。

**CI では版を固定する。** `--check` は「同じ入力なら同じバイト列」を前提にしているので、
ツールの版が上がって出力の形が変わると不一致になる（[CHANGELOG](../CHANGELOG.md) を見て
生成物を作り直す）。`npm ci` + `package-lock.json` か、`lgfx-font-tool@<版>` の明示で
固定するのがよい。

## 4. 入力（書体）

4 系統。いずれか 1 つを指定する。

| 指定 | 意味 | ラスタライズ |
| --- | --- | --- |
| `--google <family>` | キュレーション済み書体を**名前だけ**で取得（§4.1） | する |
| `--ttf <path\|url>` | 任意の TTF / OTF / WOFF / WOFF2 | する |
| `--font <name>` | 同梱ビットマップフォント（§4.2） | しない |
| `--input <path>` | 手元のビットマップフォントファイル（§4.3） | しない |

ラスタライズする 2 つは `--em` が要る（§4.5）。しない 2 つは既にビットマップなので不要で、
**取得もラスタライズも挟まらないぶん完全に決定的**である。

### 4.1 `--google`

再配布可能（SIL OFL 1.1 / Apache-2.0）と確認済みの書体から名前で選ぶ。
一覧は `web/googlefonts.js` が正で、増減する。`lgfx-font-tool build --list-google` で出す。
グリフをファームウェアに焼くことは書体の再配布にあたるため、既定ではこの範囲に絞る。

ラテン UI 系、表示・時計向け、日本語、記号、その他 CJK が入っている。

**v1 は Regular / weight 400 のみ。** 同じ書体の他のウェイトやイタリックは選べない
（ライブラリは `weight` / `italic` を持つので、必要になれば `--weight` / `--italic` で足せる）。

**この一覧は近道であって制限ではない。** 一覧に無い書体は自分で `.ttf` を入手して
`--ttf` に渡せばよい。その場合ライセンスの確認は利用者の責任になる。

取得は Google Fonts の CSS API 経由。**書体まるごと 1 本の TTF を取ってキャッシュする**
（Noto Sans JP で 5.1 MB）。CSS API は User-Agent で返す形式を変えるため、
TTF を返す User-Agent を使う。

> 参考: 現代のブラウザの User-Agent では woff2 が `unicode-range` で 124 分割されて返る。
> 必要なスライスだけ取れば桁違いに軽いが、字ごとのスライス解決を自前で持つことになり、
> **「書体に無い字」と「スライスを取り忘れた字」の区別がつかなくなる**危険がある。
> v1 は 1 本まるごとを採る。後から最適化として差し替えても外から見た挙動は変わらない。

### 4.2 `--font`（同梱フォント）

`--font lgfxJapanGothic_16` のように名前で引く。既にビットマップなので `--em` は不要で、
**ラスタライザも要らない**。

用途は 2 つ。

- **形式変換**。既存の u8g2 フォントを CellFont や BDF に変換する（UC5）
- **ラスタライザが動かない環境**での唯一の生成経路

同梱データは npm パッケージに含まれないものがあり、その場合は GitHub Pages から取得する
（`src/fonts/loader.js`）。**`--offline` はこの取得にも適用する。**
CI で使うならファイルを手元に置いて `--input`（§4.3）で読ませるほうが確実。

### 4.3 `--input`（手元のフォントファイル）

既存のビットマップフォントをパスで読む。`.u8g2` / `.bdf` / `.gfx` / C ソースなど。
形式は中身から判定し、外れるときは `--input-format <id>` で上書きする
（VLW や raw 系は判定できないので明示が要る）。C ソースに複数のフォントが入っている
場合は `--input-symbol <name>` で選ぶ。

**これが既存フォントの形式変換の入口**でもある（u8g2 → CellFont など）。
ラスタライザも取得も挟まらないので、4 系統でいちばん再現性が高い。

### 4.4 キャッシュ

取得したフォントは**ユーザのキャッシュディレクトリ**に置く。
`$XDG_CACHE_HOME/lgfx-font-tool`、未設定なら `~/.cache/lgfx-font-tool`。

**プロジェクト配下（`node_modules/.cache`）に置かない。** 書体は複数のプロジェクトで
共有できる素材であって、そのプロジェクト専用の中間生成物ではない。カレント基準にすると
**サブディレクトリから走らせるだけで数 MB を取り直す**。

`--cache-dir <path>` で変更する。CI では作業ディレクトリ内を指せば `actions/cache` に載る。
`--offline` はキャッシュのみを使い、無ければエラーにする。

### 取得元が変わったとき

キャッシュの鍵は URL なので、**一度取得したら同じバイト列が返り続ける**。
リモートが更新されても手元は変わらない。これは再現性としては望ましいが、
手元と CI で違う書体を使っている状態に気づけないと困る。

そこで**取得元フォントの SHA-256 を生成ヘッダのコメントに記録する。**

```
// Obtained : Google Fonts: Noto Sans JP
// Source   : sha256:ae7b7855e115a5966d8b1b3f80f254cc…
```

同じ入力なら同じ値なので正準出力（形式仕様 §10.4）を壊さない。書体が入れ替われば
**`git diff` に 1 行として出る**ので、`--check` が落ちた理由が読める。

さらに強く縛る手段は既にある。`--offline` でキャッシュのみに閉じるか、
`.ttf` を自分のリポジトリに置いて `--ttf ./font.ttf` を使う。
**専用のフラグ（`--expect-sha256` の類）は設けない** — まず記録して、必要になってから足す。

### 4.5 サイズ — `--em`

**`--em N` は em（デザインサイズ）を画素で指定する。**

em は書体の設計上の 1 文字ぶんの正方形で、**全角 1 文字の送り幅がちょうど em になる。**
高さではなく**横**の寸法が定義であることに注意。

```
--em 16  →  全角 1 文字の送り幅が 16 画素
```

実測（Noto Sans JP）。`--em` と全角の送り幅は奇数でも常に一致する。

| `--em` | 行の高さ | 最大の墨面 | 全角の送り幅 | ラテンの送り幅 |
| --- | --- | --- | --- | --- |
| 8 | 10 | 10 | **8** | 6 |
| 10 | 12 | 12 | **10** | 7 |
| 12 | 14 | 14 | **12** | 9 |
| 14 | 16 | 16 | **14** | 10 |
| 16 | 19 | 18 | **16** | 12 |
| 20 | 23 | 22 | **20** | 15 |
| 24 | 29 | 28 | **24** | 17 |

**行の高さは em より大きくなる。** 上下の余白と、`|` や括弧のように em を超えて伸びる字が
あるため。**「16 画素の行に収めたい」なら `--em 16` ではなく `--em 14` を選ぶ**
（この対応は書体ごとに違うので、生成時に実測値を表示する）。

ラテン専従の書体には全角の字が無いので送り幅の一致は起きないが、em は同じく尺度として働く。

| `--em`（DejaVu Sans） | 行の高さ | 最大の墨面 | `H` の送り幅 |
| --- | --- | --- | --- |
| 12 | 14 | 13 | 9 |
| 16 | 17 | 16 | 12 |
| 24 | 26 | 25 | 18 |

### なぜ「基準字の高さ」ではないのか

**em は測定を伴わないので、文字集合を変えてもスケールが動かない。** これが決め手。

以前の実装は「優先リスト `[漢 国 日 가 H E N 0]` のうち**要求した集合に入っている**字の
墨面の高さ」を尺度にしていた。この方式には 2 つの問題があった。

- **文字を 1 字足すと既存の字が縮む。** ASCII 95 字に `日` を足すと基準字が `H` から `日` に
  変わり、**既存 92 字の寸法と行の高さが変わった**（実測）。
  「文字が気軽に増減できる」という前提を壊す
- **指定値が何も保証しない。** `16` と指定しても最大の墨面は 24 画素、行の高さは 25 画素に
  なりうる（基準字が最大の字とは限らないため）

`--em` は測定をしないのでどちらも起きない。ASCII 95 字に漢字 7 字を足しても
**変化した字は 0/95**（実測）。

`--em` は同梱ビットマップフォントの命名とも一致する。`lgfxJapanGothic_16` は
全角の送り幅が 16 で、`--em 16` と同じ意味になる。

### 収まりの検査

行の高さは書体依存なので、**入るかどうかは指定ではなく検査で扱う。**

```
--max-height 16    行の高さが 16 を超えたらエラー（終了コード 1）
```

### 4.6 不足文字の補完（`--fallback`）

収録判定が正しくなったので、不足分を別の書体から埋められる。

```
lgfx-font-tool build --google Roboto --fallback google:"Noto Sans JP" \
  --em 16 --sets ascii,hiraganaKatakana,hanJaG1 \
  --format cellfont --out font.h
```

- `--fallback` は繰り返せる。**指定した順**に試す。どの書体が広いかで結果が変わらないように、
  順序は指定順に固定してある。
- 記法は入力元と同じ（`google:<family>` / パス / URL）。覚えることを増やさない。
- 埋めた文字数と内容は標準エラーに出る。
- **補完元の権利表記も出力ファイルに入る。** 埋めた側も派生元なので、書体名・作者・
  ライセンス・取得元・`sha256` を書体ごとに記録する。
- 補完はラスタライズなので `--em` が要る。

#### 既存フォントに文字を足す

`--input`（手元のビットマップフォント）にも補完が効く。**「フォント同士を連結する」機能は
用意しない。** 足りない字を補うほうが、扱う概念が少なく、出力も 1 個のフォントで済む。

```sh
# 既存の .h に漢字を足して作り直す
lgfx-font-tool build --input font.h --chars "AB温度" --em 16 \
    --fallback google:"Noto Sans JP" --format cellfont --out font.h
```

ただし**本ツールで作ったフォントなら、こちらが本筋**である。生成ヘッダには作った
コマンドが入っている（§6）ので、文字を足して同じコマンドを回すだけでよい。

```sh
# ヘッダの "Rebuild with" のコマンドに文字を足して回す
lgfx-font-tool build --google Roboto --em 16 --chars "AB温度" \
    --fallback google:"Noto Sans JP" --format cellfont --out font.h
```

全字形が同じ書体・同じ `--em` から出るので、**寸法が揃い、出力も最小になる**。
`--input` からの追加が要るのは、元の書体が手元に無い場合か、元からビットマップだった場合。

| | `--input` + `--fallback` | 元コマンドに文字を足す |
| --- | --- | --- |
| 元の書体 | 不要 | 必要 |
| 寸法 | **揃わないことがある**（下記） | 揃う |
| 出力量 | 大きくなりがち | 最小 |

**寸法が食い違うと警告する。** 基準になるのは入力フォントの行高で、補完した字形はそれに
合わない位置・大きさになりうる。黙って拡縮するほうが悪いので、両方の値を出して
`--preview` での確認を促す。

```
warning: the filled characters were drawn to different metrics than the base font.
  base: {"ascent":12,"descent":0,"lineHeight":12}
  fill: {"ascent":14,"descent":2,"lineHeight":16}
  The base font's line box is kept. Check the result with --preview.
```

**CellFont のヘッダは読み戻せない**（C ソース入力が読むのは GFXfont と u8g2）。
CellFont に文字を足すときは、ヘッダの `Rebuild with` のコマンドを回す。

## 5. 文字の指定

4 系統。**併用でき、すべて和集合になる。**

| 指定 | 例 |
| --- | --- |
| `--chars <文字列>` | `--chars "温度設定完了℃"` |
| `--charset <path>` | `--charset fonts/chars.txt`（§11） |
| `--sets <id,...>` | `--sets ascii,hiragana,hanJaG6` |
| `--template <id>` | `--template japaneseUi` |

**1 文字も残らなかったらエラー**（終了コード 1）。空のフォントは形式が許さない
（CellFont 仕様 §15.1）。

### 集合 ID とテンプレート

集合とテンプレートは `src/charsets/` の生成データが正で、**ID も字数もそこで増減する**
（実際に学年別漢字 6 件が後から増えた）。**本書には一覧も字数も載せない。**
書き写せば必ずずれる。

```
lgfx-font-tool charset --list      集合 ID・テンプレート ID と現在の字数を出す
```

軸は ラテン / かな / 漢字 / ハングル / 記号 の 5 つ。漢字は言語ごとの**累積ティア**で、
日本語は学年別（小 1〜小 6 = 教育漢字）から常用・人名用・JIS 水準へと積み上がる。

`--template` はよくある組み合わせの別名で、`--sets` の糖衣にすぎない。
**`--chars` / `--charset` / `--sets` / `--template` は併用でき、すべて和集合になる。**

## 6. 出力

`--out <path>` と `--format <id>`。**`--format` は必須で、既定はない。**
汎用ツールなので特定の形式に寄せない。省略したら形式一覧を出して終了する。

**容器は拡張子で決まる。**

| 拡張子 | 容器 |
| --- | --- |
| `.h` / `.hpp` / `.c` / `.cpp` | C ソース（配列 + 構造体） |
| それ以外 | 生ファイル（各形式のバイナリ、BDF はテキスト） |

### 対応形式

| `--format` | C ソース | 生ファイル |
| --- | --- | --- |
| `cellfont` | CellFont 構造体（形式仕様 §12） | — |
| `u8g2` | `lgfx::U8g2font` として使える（`--no-wrapper` で配列のみ） | u8g2 バイナリ |
| `gfx` | Adafruit GFX 互換。疎な集合は LovyanGFX 拡張 | **GFX1 コンテナ**（本ツール固有。Adafruit の生形式ではない） |
| `vlw` | 実行時 `loadFont` 用の配列 | VLW バイナリ |
| `bff` | 実行時 `loadFont` 用の配列。`--bpp 1\|2\|4` | BFF バイナリ |
| `bdf` | — | BDF テキスト |
| `fontx2` | — | FONTX2 バイナリ |

組み合わせが不正なら**理由を書いて終了する**
（例: `cellfont` は生ファイル出力不可、`bdf` は C ソース出力不可）。

### C ソース出力に要るもの

| 指定 | 意味 |
| --- | --- |
| `--name <ident>` | C のシンボル名。省略時は `--out` の basename を C 識別子へ正準化 |
| `--target ilp32\|avr` | CellFont の候補比較に使う `sizeof(CellFont)`（28 / 20）。既定 `ilp32` |
| `--no-wrapper` | u8g2 の `lgfx::U8g2font` 宣言を出さない |
| `--pin-version` | 再現コマンドにツールの版を書き込む（既定は書かない） |

`--target` が要るのは CellFont だけ。**対象 ABI で勝つ候補が変わる**ため、形式仕様 §10.4 が
これを生成器の入力の一部と定めている。他の形式では無視する。

#### `--no-wrapper` — u8g2 を LovyanGFX 抜きで使う

u8g2 出力のうち **LovyanGFX 固有なのは最後の 1 行だけ**である。バイト配列そのものは
上流 u8g2 が読む形式で、ライブラリ非依存である。

```c
static const uint8_t myfont_data[71] LGFXFT_PROGMEM = { ... };   // 上流 u8g2 の形式
static const lgfx::U8g2font myfont(myfont_data);                 // ここだけ LovyanGFX
```

`--no-wrapper` を付けると後者を出さず、**配列そのものをフォント記号にする**
（上流 u8g2 のフォントと同じ形）。

```c
static const uint8_t myfont[71] LGFXFT_PROGMEM = { ... };
// 使い方:  u8g2.setFont(myfont);
```

`--format u8g2` 以外に付けると引数エラー（3）にする。他の形式が宣言するのは
形式そのものが要求する型であって、外せる包みではないため。

| `--format` | 出力にライブラリ固有の型が出るか |
| --- | --- |
| `u8g2` | `lgfx::U8g2font`。`--no-wrapper` で外せる |
| `gfx`（連続 1 範囲） | `GFXfont` / `GFXglyph`。Adafruit GFX の標準型で、これが形式そのもの |
| `gfx`（疎な集合） | `lgfx::v1::GFXfont` / `EncodeRange`。LovyanGFX 拡張。**外せない**（Adafruit の `GFXfont` は単一の連続範囲しか表せない） |
| `vlw` / `bff` | 出ない。**既に配列だけ**を出している |
| `cellfont` | `CellFont` / `CellGlyph`。形式仕様 §12 の型で、特定のライブラリに属さない |

### 生成される C ソース

書体名・作者・ライセンス・入手元・収録範囲・データ量が、先頭のコメントに入る
（OFL / Apache は告知の同梱を求めるため）。**収録範囲がコメントに入るので、
`git diff` だけで「どの文字が増減したか」が読める。**

**コメントに揺れる値を入れない。** 絶対パス、取得時刻、版つきの一時 URL は正準出力を壊す
（形式仕様 §10.4）。入手元は「入力された相対パス」か「`--google <family>` の書体名」など、
**同じ入力なら同じ文字列になるものだけ**を書く。

### 再現コマンドの記録

C ソース出力の先頭コメントに、そのファイルを作ったコマンドが入る。

```
// Rebuild with:
//   npx lgfx-font-tool build --google Roboto --em 16 --chars 'AB温度' --fallback 'google:Noto Sans JP' --format cellfont --out myFont.h --name myFont
```

- **`--out` はファイル名だけを載せ、パスは載せない。** 名前は載せる価値がある。行をその
  まま回せば、回した場所にそのファイルが出来る。どのディレクトリから来たかは違う。それは
  実行した人のものだし、行に入れると同じフォントを 4 つのディレクトリに置いただけで
  4 つとも中身が違うファイルになり、生成済みヘッダをコピーして使い回せなくなる。形式仕様の
  「同じ入力なら同じバイト列」（入力＝文字集合・yAdvance・対象 ABI）からも外れる。
  絶対パスでも相対パスでも `../../elsewhere/font.h` でも、出るのは `font.h` だけ。
- **`--name` は指定が無くても必ず載せる。** シンボル名は出力そのものの一部で、既定値は
  ファイル名から取る。つまり元からファイル名で変わる値なので、ファイル名を載せても
  ぶれは増えない。正準化した後の実際の識別子を書く。
- 出力に影響しない指定（`--check` `--preview` `--preview-text` `--max-height`
  `--offline` `--cache-dir` `--json`）は載せない。`--allow-missing` は、無いと
  作り直しが止まるので載せる。
- 並び順は**入力した順ではなく固定**。同じビルドが常に同じ 1 行になり、
  出力の正準性（§6）を壊さない。
- **どれだけ長くても 1 行で出す。** `\` で折り返すと読みやすいが、続きの行も `//` の
  中なので、コピーするとシェルに渡るのはコメントだけになる。
- **`npx lgfx-font-tool` の 1 語で出す。** コマンド名をパッケージ名と同じにしてあるので、
  npx はこの 1 語だけで取得も実行もできる。事前のインストールも要らず、読む側のマシンの
  事情も行に混ざらない（§3）。
- **ツールの版は既定では書かない。`--pin-version` で書く。** 版を書かないと npx が最新を
  解決するので、出力の形が変わる版が出ていれば作り直しの結果が変わる。書けばそれは
  起きないが、代わりにツールを上げるたび全ヘッダが書き換わる。どちらの費用を払うかは
  プロジェクト次第なので、既定にせずフラグにした。`--pin-version` は**自分自身も
  記録する**ので、書かれたコマンドをそのまま回せば同じヘッダになる。

```
// Rebuild with:
//   npx lgfx-font-tool@2.3.0 build --font lgfxJapanGothic_8 --sets digits --format cellfont --out f.h --name f --pin-version
```
- **`--chars` の値は 1 文字でも必ず引用する。** `--chars ℃` はシェル的には引用が要らないが、
  引用が無いと片方が消えたように読める。内容を表す指定なので、どこまでが値かを示す。
  先頭が `-` の値と空文字も、読み戻すとフラグになったり消えたりするので引用する。
- **作業ディレクトリの外を指すパスはファイル名だけに丸める。** 書き方は関係なく、
  解決した先で判断する。`/home/誰か/x.ttf` も `../../どこか/x.ttf` も `x.ttf` になる。
  ホームディレクトリの構成が出力に混ざらず、環境をまたいでも同じ行になる。代わりに、
  手元の TTF は自分で置き直す必要がある。
- **作業ディレクトリの中のパスはそのまま残す。** `--charset fonts/chars.txt` のような
  プロジェクト内の相対パスは、漏れる情報ではなく、そのファイルを作り直すのに必要な情報。
  区切り文字と `./` は正規化するので、`fonts/x.txt` と `./fonts/x.txt` は同じ 1 行になる。

同じフォントを別のディレクトリに置いてもバイト一致する。

```sh
$ for d in a b c d; do
    lgfx-font-tool build --font lgfxJapanGothic_8 --chars '℃' --sets digits \
        --format cellfont --name tgfxClock --out $d/tgfx_clock.h
  done
$ md5sum */tgfx_clock.h
d5f4f51c84f137f73b6b0562b41250f3  a/tgfx_clock.h
d5f4f51c84f137f73b6b0562b41250f3  b/tgfx_clock.h
d5f4f51c84f137f73b6b0562b41250f3  c/tgfx_clock.h
d5f4f51c84f137f73b6b0562b41250f3  d/tgfx_clock.h
```

**`--name` を省いた場合は別物になる。** 既定のシンボル名は `--out` の basename から作るので、
置き場所ごとにファイル名が違えばシンボル名も違う。使い回すつもりなら `--name` を明示する。

## 7. 検証モード

```
lgfx-font-tool build ... --check
```

**主出力（`--out`）を書かず、既存のものと一致するかだけを見る。** CI 用。
プレビューは主出力ではないので `--check` でも書ける。
不一致なら差分の要点を出して終了コード 2。**既存の出力が無い場合も 2**（未生成 = 不一致）。

## 8. 確認用の画像

**画像は生成物ではなく生成物の確認**。凝らない。

| 指定 | 出力 |
| --- | --- |
| `--preview <path.png>` | グリフ一覧（頼んだ文字が入ったか） |
| `--preview <path.png> --preview-text "文字列"` | 文字列見本（実際の文言が読めるか） |

グリフ一覧は 1 行 16 セル、コードポイント順で、各セルに薄い枠が付く。**最後のグリフより
後ろのセルには斜線を引く。** 何も引かないと、何も描かないグリフ — スペース — と見分けが
つかず、最終行が途中まで埋まっている絵が、どちらを見せているのか言えなくなるため。
白いセルに枠があれば「何も描かないグリフ」、斜線なら「そこにグリフは無い」。

出力先はプロジェクトが決める。**コミットするか、`.gitignore` に入れるか、
CI のアーティファクトに上げるかはツールの関知するところではない。**

PNG は 8bit グレースケール。依存は `node:zlib` のみ。

## 9. `inspect`

既存フォントを読んで内容を出す（UC2 / UC9 の CLI 版）。

```
lgfx-font-tool inspect <file> [--input-format <id>] [--input-symbol <name>] [--json]
```

出すもの: 形式、収録字数、収録範囲、メトリクス（em / 行高 / ascent / descent）、
全形式でのデータ量、読み込み時の issues。

- 形式は自動判定し、`--input-format` で上書きできる（VLW や raw 系は判定できないので明示が要る）
- C ソースに複数のフォントがあれば一覧を出し、`--input-symbol` で 1 つ選ぶ
- `--json` は機械可読出力。CI で予算検査などに使う
- 読めなければ終了コード 1。壊れていても読めるところまで読み、issues に出す

## 10. 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 成功 |
| 1 | 生成エラー（収録漏れ、`--max-height` 超過、フィールド範囲外、形式と容器の不整合など） |
| 2 | `--check` の不一致（既存の出力が無い場合も 2） |
| 3 | 引数の誤り（`--format` 省略時の形式一覧表示を含む） |

**書体に無い文字は既定でエラー（コード 1）。** 黙って空白を焼き込むと実機で気づくまで
分からないため。`--fallback` で別の書体から埋める（§4.6）か、`--allow-missing` で
警告に落とす。

## 11. 文字集合ファイル

`--charset` に渡すテキスト。`src/charsets/charsets.js` と同じ語彙を使う
（Web UI と同じ言葉になる）。

```
# 画面の固定文言
@ascii
@symUnits
U+00B0-U+00B1
温度湿度設定完了異常
```

| 行 | 意味 |
| --- | --- |
| `# ...` | コメント |
| `@<id>` | 集合 ID（§5） |
| `U+XXXX` / `U+XXXX-U+YYYY` | コードポイントと範囲 |
| その他 | その行に現れる文字すべて |

### 正準化

```
lgfx-font-tool charset fonts/chars.txt              # 正準化は既定の動作
lgfx-font-tool charset fonts/chars.txt --normalize  # 明示形。同じ
```

**リテラル行ごとに正準化する。行をまたいで文字を動かさない。**

| 規則 | |
| --- | --- |
| 単位 | **1 行ごと**。行内で重複除去し、コードポイント順に並べ替える |
| 行の順序 | 変えない。コメントと行の対応が保たれる |
| 行をまたぐ重複 | **残す**。`@ascii` と重複するリテラルも消さない |
| `@名前` の展開 | しない（**なぜその文字が要るのかが消えるため**） |
| 文字コード | UTF-8。BOM は保つ。改行は LF に統一 |
| 書き込み | 標準出力へ。`--write` のときだけ同一ディレクトリの一時ファイル経由で置換する |

行をまたいで集約しないのは、**「どの行へ戻すか」に正解が無い**ため。行内に閉じれば
規則は一意で、コメントの意味も壊れない。

`charset --list` は集合とテンプレートの ID・字数を出す（§5）。
`charset --expand` は `@名前` を実際の文字に展開して吐く。**コピペで自分の集合を作る出発点**。

## 12. 使用例

```sh
# 単発。内蔵フォントから今欲しい文字だけ
npx lgfx-font-tool build --font lgfxJapanGothic_16 --chars "温度設定完了" \
    --format cellfont --out font.h

# Google Fonts から名前だけで
npx lgfx-font-tool build --google "Noto Sans JP" --em 16 \
    --sets ascii,hiragana,hanJaG6 --chars "℃" --format cellfont --out font.h

# 手持ちの TTF から、確認画像つき
npx lgfx-font-tool build --ttf ./MyFont.ttf --em 12 --charset chars.txt \
    --format cellfont --out font.h --preview font.png

# 形式を変えて
npx lgfx-font-tool build --ttf ./MyFont.ttf --em 12 --sets ascii --format u8g2 --out font.u8g2

# 欧文書体に無い字を別書体から埋める
npx lgfx-font-tool build --google Roboto --fallback google:"Noto Sans JP" --em 16 \
    --sets ascii --chars "温度設定" --format cellfont --out font.h

# 上流 u8g2 で使う（LovyanGFX の型を出さない）
npx lgfx-font-tool build --ttf ./MyFont.ttf --em 12 --sets ascii \
    --format u8g2 --no-wrapper --out font.h

# 継続利用（package.json）
"scripts": {
  "font": "lgfx-font-tool build --google 'Noto Sans JP' --em 16 --charset fonts/chars.txt --format cellfont --out src/font.h --preview fonts/preview.png"
}
```

日常はこうなる。

```
$ vim fonts/chars.txt
$ npm run font
  src/font.h   1,473 B (+29)   文字 191 (+1)   行高 16   最大墨面 16
               固定 4x8×95 + 固定 8x9×96   連鎖 2
$ git add -A && git commit
```

**`(+29)` と `(+1)` が要点。** 何を足したらいくら増えたかが毎回わかる。
既存の出力ファイルがあればそこから差分を出す。

**行高と最大墨面を毎回出す。** `--em` は横の寸法なので、縦が何画素になるかは
書体を替えるまで分からない。表示していれば `--max-height` を付けていなくても気づける。

## 13. 実装の前提

### 13.1 ラスタライザ

`src/gen/rasterize.js` はブラウザの `FontFace` + Canvas を使うため、Node では
`CapabilityError('RASTERIZER_UNAVAILABLE')` になる。CLI はこれを次の形で埋める。

| 項目 | 決定 |
| --- | --- |
| 実装 | **`@napi-rs/canvas`**（Skia）＋ 約 40 行のシム |
| シムが用意するもの | `FontFace` / `document.fonts` / `OffscreenCanvas` |
| 既存コードの変更 | **不要**。`rasterize.js` をそのまま動かす |
| 依存の種類 | ネイティブ（プリビルド配布。ビルドツール不要） |
| バージョン | `package.json` で固定 |
| 画素の一致範囲 | **同一環境で決定的であればよい。** ブラウザとの画素一致は求めない |

検証済みのこと。

- ASCII 95 字 + 記号を 9 / 12 / 16 px で生成でき、収録判定も含めて動く
- **別プロセスで 3 回実行してバイト一致**（同一マシン・同一版）
- woff2 も読める

**未検証: OS と CPU の組み合わせ。** 確認したのは Linux x64 のみで、
`@napi-rs/canvas` のプリビルドが無い環境の挙動は見ていない。

#### 収録判定は cmap で行う

ライブラリの収録判定は、対象書体で描いた結果と総称フォント（`serif` / `monospace`）で
描いた結果を比べる方式である。ブラウザではこれで正しく動く。`FontFace` の
`unicode-range` が、登録した書体を範囲外の文字に一切使わせないためである。

**Node では成り立たない。** Skia のフォント登録に `unicode-range` に相当する仕組みがなく、
書体が持たない字は Skia が勝手にシステムフォントで代替描画してしまう。比較方式はこれを
「書体が持っている」と読む。実測では、漢字を持たない DejaVu Sans に `温` を要求すると
152 px 相当の字形が返ってきた。

登録の隔離では解決しない。`GlobalFonts.removeAll()` を先に呼んでも後に呼んでも
（実測）書体数は 162 に戻り、すべての書体が同じ結果を返すようになるため、
`A` すら「持っていない」と判定される。つまり悪化する。

そこで CLI は、**フォントファイルの `cmap` を自分で読んで収録文字を確定する**
（[bin/coverage.js](../bin/coverage.js)）。ラスタライザに渡すのは、その書体が実際に
持っている符号位置だけになる。読むのは `cmap` だけで、字形も何も解釈しない。
書式 0 / 4 / 6 / 12 に対応する。仕様書 §2.3（ライブラリはフォントの表を解析しない）は
そのままで、この処理は `bin/` 側に閉じている。

| 入力 | 収録判定 |
| --- | --- |
| TTF / OTF / TTC | `cmap` から確定 |
| WOFF / WOFF2 | **判定できない。**`cmap` が圧縮されているため、警告を出して絞り込みなしで通す |

WOFF / WOFF2 では、書体が持たない字がシステムフォントで描かれる可能性が残る。
確実にしたい場合は非圧縮の TTF / OTF を渡す。

### 13.2 依存とネットワーク

**CLI は同じパッケージに同梱する**（別パッケージにしない）。`package.json` の `bin` から
`lgfx-font-tool` を提供する。

ラスタライザは **`optionalDependencies`** とする。

| | |
| --- | --- |
| `npm i lgfx-font-tool` | **入る**（プラットフォーム別バイナリ 33 MB）。TTF がそのまま使える |
| `npm i --omit=optional` | 入らない。`--ttf` / `--google` はインストール方法を案内して終了（コード 1） |
| プリビルドが無い OS / CPU | **`npm install` 自体は成功する。** 実行時に §13.2 のメッセージが出る |

**`optionalDependencies` は既定でインストールされる。** 「任意」なのは*入るかどうか*ではなく、
**入れられなくても `npm install` を失敗させない**という意味である。

**2 つの失敗を言い分ける。** パッケージが無い（`ERR_MODULE_NOT_FOUND`）のと、
入っているがこのプラットフォーム向けのバイナリが無い（`Cannot find native binding`）のは
別の話で、後者に「install しろ」と言うと**入れ直しても同じエラーに戻る**。

```
パッケージが無い    → npm install @napi-rs/canvas
バイナリが無い      → @napi-rs/canvas has no prebuilt binary for this platform
                      (linux/x64). Reinstalling will not help.
                      Use --font or --input with a bitmap font, …
```

**`dependencies` にしない理由。** 実質的な差は 1 つしかない。
どちらでも既定で 33 MB が入るので、**違うのはプリビルドが無い環境での挙動だけ**である。

| 宣言 | プリビルドが無い OS / CPU |
| --- | --- |
| `dependencies` | `npm install` が**失敗しうる**。ライブラリだけ使いたい人まで巻き添えになる |
| `optionalDependencies` | **インストールは成功し**、TTF を使ったときだけ落ちる |

ラスタライザは 4 系統の入力のうち 2 つでしか要らないので、それが無いからといって
パッケージ全体を入れられなくするのは重すぎる。だから任意依存を採る。

`--omit=optional` を使う人と、プリビルドが無い環境の人には、
「実行してエラーが出たら追加インストールする」流れを案内する（§13.2 のメッセージ）。

- **ライブラリ本体は実行時依存ゼロのまま**（spec §3 判断 #2）。
  `src/` は `@napi-rs/canvas` を参照しない。シムは `bin/` にある
- ネットワークに触るのは `--google` / `--ttf <url>` / `--font`（同梱データの取得）。
  **`--offline` は 3 つすべてに適用する**

## 14. 決めたこと・残っていること

| 論点 | 決定 |
| --- | --- |
| プリビルドが無い OS / CPU | 動かない。**そう言う**（§13.2）。`--font` / `--input` は動く |
| リモートが変わったとき | キャッシュが実質の固定。**取得元の SHA-256 をヘッダに記録**して差分に出す（§4.4） |
| キャッシュの位置 | **ユーザのキャッシュディレクトリ**。`--cache-dir` で変更（§4.4） |
| 収録判定 | **フォントの `cmap` を読む**（§13.1）。描画結果の比較は Node では成り立たない |
| 不足文字 | `--fallback` で別書体から埋める。**ビットマップ同士は自動化しない**（§4.6） |
| 出力の再現 | **コマンドをヘッダのコメントに記録**する。作業ディレクトリ外の絶対パスは丸める（§6） |
| ライブラリ固有の型 | `u8g2` は `--no-wrapper` で外せる。`gfx` の疎な集合は外せない（§6） |
