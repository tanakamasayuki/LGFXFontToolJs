# lgfx-font — CLI 仕様

[English](./cli.en.md)

- 状態: **v1 — 実装済み・テスト済み**（未決は §14）
- 対象読者: この CLI を実装する人・使う人
- 最終更新: 2026-08-28
- 本書の内容は `bin/` に実装があり、`test/cli.test.js` が終了コードと出力の契約を検査する

## 1. 位置づけ

**Web UI（Viewer / Generator / Converter / Inspector）と役割を分ける。**

Web UI は書体を探し、文字集合を組み立て、目で見て決めるための道具。CLI が引き受けるのは
**ブラウザに原理的にできないこと**だけにする。

| | Web UI | CLI |
| --- | --- | --- |
| 書体を探す・選ぶ | ○ | × |
| 文字集合を組み立てて眺める | ○ | × |
| 一度だけ変換して落とす | ○ | △ |
| **同じ操作を毎ビルド繰り返す** | × | **○** |
| **同じ結果を CI で再現する** | × | **○** |

### やらないこと

- **ソースコードの走査**（どの文字を使っているかの自動収集）— プロジェクト固有なので利用者側
- **git 操作** — CI の仕事
- **書体選び・文字集合の組み立て UI** — Web UI の仕事
- **凝った画像出力** — 画像は生成物ではなく**生成物の確認**（§8）

## 2. 設計の指針

1. **引数だけで完結する。** 設定ファイルを書かないと何も出ない道具にしない。
   単発利用が起点で、継続利用は「引数を保存したもの」にすぎない
2. **簡潔さを優先する。** ネットワークとローカルの資源は多少使ってよい。
   数 MB の取得やキャッシュより、**コマンドと概念の少なさ**を優先する
3. **出力結果が正。** 同じ環境で同じ入力なら同じバイト列が出る

### 継続利用は「同じコマンドの別モード」

| 使い方 | 形 |
| --- | --- |
| 単発 | `lgfx-font build <引数>` |
| 日常の増減 | `npm run font`（= 保存した `build`） |
| CI 検証 | `npm run font -- --check` |

**設定ファイルは作らない。** 複数ターゲットは npm script の `&&` で足りる。
必要になれば「保存された引数」として後から互換に足せる。

## 3. コマンド

```
lgfx-font build   [オプション]              フォントデータを作る（§4-§8）
lgfx-font inspect <file> [オプション]       既存フォントを調べる（§9）
lgfx-font charset <file> [オプション]       文字集合ファイルの正準化・一覧（§11）
```

3 つ。`build` が本体で、他の 2 つは補助。**`build` の指定はすべてオプション**で、
位置引数は取らない（入力・文字・出力の 3 種をフラグで組み合わせる）。

## 4. 入力（書体）

4 系統。いずれか 1 つを指定する。

| 指定 | 意味 | ラスタライズ |
| --- | --- | --- |
| `--google <family>` | キュレーション済み書体を**名前だけ**で取得（§4.1） | する |
| `--ttf <path\|url>` | 任意の TTF / OTF / WOFF / WOFF2 | する |
| `--font <name>` | 同梱ビットマップフォント（§4.2） | しない |
| `--input <path>` | 手元のビットマップフォントファイル（§4.3） | しない |

ラスタライズする 2 つは `--em` が要る（§4.5）。しない 2 つは既にビットマップなので不要で、
**取得もラスタライズも挟まらないぶん完全に決定的**である。

### 4.1 `--google`

再配布可能（SIL OFL 1.1 / Apache-2.0）と確認済みの書体から名前で選ぶ。
一覧は `web/googlefonts.js` が正で、増減する。`lgfx-font build --list-google` で出す。
グリフをファームウェアに焼くことは書体の再配布にあたるため、既定ではこの範囲に絞る。

ラテン UI 系、表示・時計向け、日本語、記号、その他 CJK が入っている。

**v1 は Regular / weight 400 のみ。** 同じ書体の他のウェイトやイタリックは選べない
（ライブラリは `weight` / `italic` を持つので、必要になれば `--weight` / `--italic` で足せる）。

**この一覧は近道であって制限ではない。** 一覧に無い書体は自分で `.ttf` を入手して
`--ttf` に渡せばよい。その場合ライセンスの確認は利用者の責任になる。

取得は Google Fonts の CSS API 経由。**書体まるごと 1 本の TTF を取ってキャッシュする**
（Noto Sans JP で 5.1 MB）。CSS API は User-Agent で返す形式を変えるため、
TTF を返す User-Agent を使う。

> 参考: 現代のブラウザの User-Agent では woff2 が `unicode-range` で 124 分割されて返る。
> 必要なスライスだけ取れば桁違いに軽いが、字ごとのスライス解決を自前で持つことになり、
> **「書体に無い字」と「スライスを取り忘れた字」の区別がつかなくなる**危険がある。
> v1 は 1 本まるごとを採る。後から最適化として差し替えても外から見た挙動は変わらない。

### 4.2 `--font`（同梱フォント）

`--font lgfxJapanGothic_16` のように名前で引く。既にビットマップなので `--em` は不要で、
**ラスタライザも要らない**。

用途は 2 つ。

- **形式変換**。既存の u8g2 フォントを CellFont や BDF に変換する（UC5）
- **ラスタライザが動かない環境**での唯一の生成経路

同梱データは npm パッケージに含まれないものがあり、その場合は GitHub Pages から取得する
（`src/fonts/loader.js`）。**`--offline` はこの取得にも適用する。**
CI で使うならファイルを手元に置いて `--input`（§4.3）で読ませるほうが確実。

### 4.3 `--input`（手元のフォントファイル）

既存のビットマップフォントをパスで読む。`.u8g2` / `.bdf` / `.gfx` / C ソースなど。
形式は中身から判定し、外れるときは `--input-format <id>` で上書きする
（VLW や raw 系は判定できないので明示が要る）。C ソースに複数のフォントが入っている
場合は `--input-symbol <name>` で選ぶ。

**これが既存フォントの形式変換の入口**でもある（u8g2 → CellFont など）。
ラスタライザも取得も挟まらないので、4 系統でいちばん再現性が高い。

### 4.4 キャッシュ

取得したフォントは**ユーザのキャッシュディレクトリ**に置く。
`$XDG_CACHE_HOME/lgfx-font-tool`、未設定なら `~/.cache/lgfx-font-tool`。

**プロジェクト配下（`node_modules/.cache`）に置かない。** 書体は複数のプロジェクトで
共有できる素材であって、そのプロジェクト専用の中間生成物ではない。カレント基準にすると
**サブディレクトリから走らせるだけで数 MB を取り直す**。

`--cache-dir <path>` で変更する。CI では作業ディレクトリ内を指せば `actions/cache` に載る。
`--offline` はキャッシュのみを使い、無ければエラーにする。

### 取得元が変わったとき

キャッシュの鍵は URL なので、**一度取得したら同じバイト列が返り続ける**。
リモートが更新されても手元は変わらない。これは再現性としては望ましいが、
手元と CI で違う書体を使っている状態に気づけないと困る。

そこで**取得元フォントの SHA-256 を生成ヘッダのコメントに記録する。**

```
// Obtained : Google Fonts: Noto Sans JP
// Source   : sha256:ae7b7855e115a5966d8b1b3f80f254cc…
```

同じ入力なら同じ値なので正準出力（形式仕様 §10.4）を壊さない。書体が入れ替われば
**`git diff` に 1 行として出る**ので、`--check` が落ちた理由が読める。

さらに強く縛る手段は既にある。`--offline` でキャッシュのみに閉じるか、
`.ttf` を自分のリポジトリに置いて `--ttf ./font.ttf` を使う。
**専用のフラグ（`--expect-sha256` の類）は設けない** — まず記録して、必要になってから足す。

### 4.5 サイズ — `--em`

**`--em N` は em（デザインサイズ）を画素で指定する。**

em は書体の設計上の 1 文字ぶんの正方形で、**全角 1 文字の送り幅がちょうど em になる。**
高さではなく**横**の寸法が定義であることに注意。

```
--em 16  →  全角 1 文字の送り幅が 16 画素
```

実測（Noto Sans JP）。`--em` と全角の送り幅は奇数でも常に一致する。

| `--em` | 行の高さ | 最大の墨面 | 全角の送り幅 | ラテンの送り幅 |
| --- | --- | --- | --- | --- |
| 8 | 10 | 10 | **8** | 6 |
| 10 | 12 | 12 | **10** | 7 |
| 12 | 14 | 14 | **12** | 9 |
| 14 | 16 | 16 | **14** | 10 |
| 16 | 19 | 18 | **16** | 12 |
| 20 | 23 | 22 | **20** | 15 |
| 24 | 29 | 28 | **24** | 17 |

**行の高さは em より大きくなる。** 上下の余白と、`|` や括弧のように em を超えて伸びる字が
あるため。**「16 画素の行に収めたい」なら `--em 16` ではなく `--em 14` を選ぶ**
（この対応は書体ごとに違うので、生成時に実測値を表示する）。

ラテン専従の書体には全角の字が無いので送り幅の一致は起きないが、em は同じく尺度として働く。

| `--em`（DejaVu Sans） | 行の高さ | 最大の墨面 | `H` の送り幅 |
| --- | --- | --- | --- |
| 12 | 14 | 13 | 9 |
| 16 | 17 | 16 | 12 |
| 24 | 26 | 25 | 18 |

### なぜ「基準字の高さ」ではないのか

**em は測定を伴わないので、文字集合を変えてもスケールが動かない。** これが決め手。

以前の実装は「優先リスト `[漢 国 日 가 H E N 0]` のうち**要求した集合に入っている**字の
墨面の高さ」を尺度にしていた。この方式には 2 つの問題があった。

- **文字を 1 字足すと既存の字が縮む。** ASCII 95 字に `日` を足すと基準字が `H` から `日` に
  変わり、**既存 92 字の寸法と行の高さが変わった**（実測）。
  「文字が気軽に増減できる」という前提を壊す
- **指定値が何も保証しない。** `16` と指定しても最大の墨面は 24 画素、行の高さは 25 画素に
  なりうる（基準字が最大の字とは限らないため）

`--em` は測定をしないのでどちらも起きない。ASCII 95 字に漢字 7 字を足しても
**変化した字は 0/95**（実測）。

`--em` は同梱ビットマップフォントの命名とも一致する。`lgfxJapanGothic_16` は
全角の送り幅が 16 で、`--em 16` と同じ意味になる。

### 収まりの検査

行の高さは書体依存なので、**入るかどうかは指定ではなく検査で扱う。**

```
--max-height 16    行の高さが 16 を超えたらエラー（終了コード 1）
```

## 5. 文字の指定

4 系統。**併用でき、すべて和集合になる。**

| 指定 | 例 |
| --- | --- |
| `--chars <文字列>` | `--chars "温度設定完了℃"` |
| `--charset <path>` | `--charset fonts/chars.txt`（§11） |
| `--sets <id,...>` | `--sets ascii,hiragana,hanJaG6` |
| `--template <id>` | `--template japaneseUi` |

**1 文字も残らなかったらエラー**（終了コード 1）。空のフォントは形式が許さない
（CellFont 仕様 §15.1）。

### 集合 ID とテンプレート

集合とテンプレートは `src/charsets/` の生成データが正で、**ID も字数もそこで増減する**
（実際に学年別漢字 6 件が後から増えた）。**本書には一覧も字数も載せない。**
書き写せば必ずずれる。

```
lgfx-font charset --list      集合 ID・テンプレート ID と現在の字数を出す
```

軸は ラテン / かな / 漢字 / ハングル / 記号 の 5 つ。漢字は言語ごとの**累積ティア**で、
日本語は学年別（小 1〜小 6 = 教育漢字）から常用・人名用・JIS 水準へと積み上がる。

`--template` はよくある組み合わせの別名で、`--sets` の糖衣にすぎない。
**`--chars` / `--charset` / `--sets` / `--template` は併用でき、すべて和集合になる。**

## 6. 出力

`--out <path>` と `--format <id>`。**`--format` は必須で、既定はない。**
汎用ツールなので特定の形式に寄せない。省略したら形式一覧を出して終了する。

**容器は拡張子で決まる。**

| 拡張子 | 容器 |
| --- | --- |
| `.h` / `.hpp` / `.c` / `.cpp` | C ソース（配列 + 構造体） |
| それ以外 | 生ファイル（各形式のバイナリ、BDF はテキスト） |

### 対応形式

| `--format` | C ソース | 生ファイル |
| --- | --- | --- |
| `cellfont` | CellFont 構造体（形式仕様 §12） | — |
| `u8g2` | `lgfx::U8g2font` として使える | u8g2 バイナリ |
| `gfx` | Adafruit GFX 互換。疎な集合は LovyanGFX 拡張 | **GFX1 コンテナ**（本ツール固有。Adafruit の生形式ではない） |
| `vlw` | 実行時 `loadFont` 用の配列 | VLW バイナリ |
| `bff` | 実行時 `loadFont` 用の配列。`--bpp 1\|2\|4` | BFF バイナリ |
| `bdf` | — | BDF テキスト |
| `fontx2` | — | FONTX2 バイナリ |

組み合わせが不正なら**理由を書いて終了する**
（例: `cellfont` は生ファイル出力不可、`bdf` は C ソース出力不可）。

### C ソース出力に要るもの

| 指定 | 意味 |
| --- | --- |
| `--name <ident>` | C のシンボル名。省略時は `--out` の basename を C 識別子へ正準化 |
| `--target ilp32\|avr` | CellFont の候補比較に使う `sizeof(CellFont)`（28 / 20）。既定 `ilp32` |

`--target` が要るのは CellFont だけ。**対象 ABI で勝つ候補が変わる**ため、形式仕様 §10.4 が
これを生成器の入力の一部と定めている。他の形式では無視する。

### 生成される C ソース

書体名・作者・ライセンス・入手元・収録範囲・データ量が、先頭のコメントに入る
（OFL / Apache は告知の同梱を求めるため）。**収録範囲がコメントに入るので、
`git diff` だけで「どの文字が増減したか」が読める。**

**コメントに揺れる値を入れない。** 絶対パス、取得時刻、版つきの一時 URL は正準出力を壊す
（形式仕様 §10.4）。入手元は「入力された相対パス」か「`--google <family>` の書体名」など、
**同じ入力なら同じ文字列になるものだけ**を書く。

## 7. 検証モード

```
lgfx-font build ... --check
```

**主出力（`--out`）を書かず、既存のものと一致するかだけを見る。** CI 用。
プレビューは主出力ではないので `--check` でも書ける。
不一致なら差分の要点を出して終了コード 2。**既存の出力が無い場合も 2**（未生成 = 不一致）。

## 8. 確認用の画像

**画像は生成物ではなく生成物の確認**。凝らない。

| 指定 | 出力 |
| --- | --- |
| `--preview <path.png>` | グリフ一覧（頼んだ文字が入ったか） |
| `--preview <path.png> --preview-text "文字列"` | 文字列見本（実際の文言が読めるか） |

出力先はプロジェクトが決める。**コミットするか、`.gitignore` に入れるか、
CI のアーティファクトに上げるかはツールの関知するところではない。**

PNG は 8bit グレースケール。依存は `node:zlib` のみ。

## 9. `inspect`

既存フォントを読んで内容を出す（UC2 / UC9 の CLI 版）。

```
lgfx-font inspect <file> [--input-format <id>] [--input-symbol <name>] [--json]
```

出すもの: 形式、収録字数、収録範囲、メトリクス（em / 行高 / ascent / descent）、
全形式でのデータ量、読み込み時の issues。

- 形式は自動判定し、`--input-format` で上書きできる（VLW や raw 系は判定できないので明示が要る）
- C ソースに複数のフォントがあれば一覧を出し、`--input-symbol` で 1 つ選ぶ
- `--json` は機械可読出力。CI で予算検査などに使う
- 読めなければ終了コード 1。壊れていても読めるところまで読み、issues に出す

## 10. 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 成功 |
| 1 | 生成エラー（収録漏れ、`--max-height` 超過、フィールド範囲外、形式と容器の不整合など） |
| 2 | `--check` の不一致（既存の出力が無い場合も 2） |
| 3 | 引数の誤り（`--format` 省略時の形式一覧表示を含む） |

**書体に無い文字は既定でエラー（コード 1）。** 黙って空白を焼き込むと実機で気づくまで
分からないため。`--allow-missing` で警告に落とせる。

## 11. 文字集合ファイル

`--charset` に渡すテキスト。`src/charsets/charsets.js` と同じ語彙を使う
（Web UI と同じ言葉になる）。

```
# 画面の固定文言
@ascii
@symUnits
U+00B0-U+00B1
温度湿度設定完了異常
```

| 行 | 意味 |
| --- | --- |
| `# ...` | コメント |
| `@<id>` | 集合 ID（§5） |
| `U+XXXX` / `U+XXXX-U+YYYY` | コードポイントと範囲 |
| その他 | その行に現れる文字すべて |

### 正準化

```
lgfx-font charset fonts/chars.txt              # 正準化は既定の動作
lgfx-font charset fonts/chars.txt --normalize  # 明示形。同じ
```

**リテラル行ごとに正準化する。行をまたいで文字を動かさない。**

| 規則 | |
| --- | --- |
| 単位 | **1 行ごと**。行内で重複除去し、コードポイント順に並べ替える |
| 行の順序 | 変えない。コメントと行の対応が保たれる |
| 行をまたぐ重複 | **残す**。`@ascii` と重複するリテラルも消さない |
| `@名前` の展開 | しない（**なぜその文字が要るのかが消えるため**） |
| 文字コード | UTF-8。BOM は保つ。改行は LF に統一 |
| 書き込み | 標準出力へ。`--write` のときだけ同一ディレクトリの一時ファイル経由で置換する |

行をまたいで集約しないのは、**「どの行へ戻すか」に正解が無い**ため。行内に閉じれば
規則は一意で、コメントの意味も壊れない。

`charset --list` は集合とテンプレートの ID・字数を出す（§5）。
`charset --expand` は `@名前` を実際の文字に展開して吐く。**コピペで自分の集合を作る出発点**。

## 12. 使用例

```sh
# 単発。内蔵フォントから今欲しい文字だけ
npx lgfx-font build --font lgfxJapanGothic_16 --chars "温度設定完了" \
    --format cellfont --out font.h

# Google Fonts から名前だけで
npx lgfx-font build --google "Noto Sans JP" --em 16 \
    --sets ascii,hiragana,hanJaG6 --chars "℃" --format cellfont --out font.h

# 手持ちの TTF から、確認画像つき
npx lgfx-font build --ttf ./MyFont.ttf --em 12 --charset chars.txt \
    --format cellfont --out font.h --preview font.png

# 形式を変えて
npx lgfx-font build --ttf ./MyFont.ttf --em 12 --sets ascii --format u8g2 --out font.u8g2

# 継続利用（package.json）
"scripts": {
  "font": "lgfx-font build --google 'Noto Sans JP' --em 16 --charset fonts/chars.txt --format cellfont --out src/font.h --preview fonts/preview.png"
}
```

日常はこうなる。

```
$ vim fonts/chars.txt
$ npm run font
  src/font.h   1,473 B (+29)   文字 191 (+1)   行高 16   最大墨面 16
               固定 4x8×95 + 固定 8x9×96   連鎖 2
$ git add -A && git commit
```

**`(+29)` と `(+1)` が要点。** 何を足したらいくら増えたかが毎回わかる。
既存の出力ファイルがあればそこから差分を出す。

**行高と最大墨面を毎回出す。** `--em` は横の寸法なので、縦が何画素になるかは
書体を替えるまで分からない。表示していれば `--max-height` を付けていなくても気づける。

## 13. 実装の前提

### 13.1 ラスタライザ

`src/gen/rasterize.js` はブラウザの `FontFace` + Canvas を使うため、Node では
`CapabilityError('RASTERIZER_UNAVAILABLE')` になる。CLI はこれを次の形で埋める。

| 項目 | 決定 |
| --- | --- |
| 実装 | **`@napi-rs/canvas`**（Skia）＋ 約 40 行のシム |
| シムが用意するもの | `FontFace` / `document.fonts` / `OffscreenCanvas` |
| 既存コードの変更 | **不要**。`rasterize.js` をそのまま動かす |
| 依存の種類 | ネイティブ（プリビルド配布。ビルドツール不要） |
| バージョン | `package.json` で固定 |
| 画素の一致範囲 | **同一環境で決定的であればよい。** ブラウザとの画素一致は求めない |

検証済みのこと。

- ASCII 95 字 + 記号を 9 / 12 / 16 px で生成でき、収録判定も含めて動く
- **別プロセスで 3 回実行してバイト一致**（同一マシン・同一版）
- woff2 も読める

**未検証: OS と CPU の組み合わせ。** 確認したのは Linux x64 のみで、
`@napi-rs/canvas` のプリビルドが無い環境の挙動は見ていない。

**注意点。** 収録判定は総称フォント（`serif` / `monospace`）との比較で行うため、
**ホストのフォント設定を継承してはならない。** 対象書体とフォールバックだけを
CLI が明示的に登録する。継承すると、書体が持たない字をシステムフォントが描いてしまい
「収録されている」と誤判定する（実測で確認）。

### 13.2 依存とネットワーク

**CLI は同じパッケージに同梱する**（別パッケージにしない）。`package.json` の `bin` から
`lgfx-font` を提供する。

ラスタライザは **`optionalDependencies`** とする。

| | |
| --- | --- |
| 既定 | 入らない。`npm i lgfx-font-tool` は追加のバイナリを引かない |
| TTF を使うとき | `npm i @napi-rs/canvas` を利用者が足す |
| 足さずに `--ttf` / `--google` を指定したら | その場でインストール方法を案内して終了（コード 1） |

**2 つの失敗を言い分ける。** パッケージが無い（`ERR_MODULE_NOT_FOUND`）のと、
入っているがこのプラットフォーム向けのバイナリが無い（`Cannot find native binding`）のは
別の話で、後者に「install しろ」と言うと**入れ直しても同じエラーに戻る**。

```
パッケージが無い    → npm install @napi-rs/canvas
バイナリが無い      → @napi-rs/canvas has no prebuilt binary for this platform
                      (linux/x64). Reinstalling will not help.
                      Use --font or --input with a bitmap font, …
```

**必須依存にしない理由は 2 つ。**

1. **プラットフォーム別バイナリが 33 MB ある。** ライブラリだけ使う人、同梱フォントや
   既存のフォントファイルしか扱わない人には要らない
2. **必須にしても失敗の形が良くならない。** `@napi-rs/canvas` 自身がプラットフォーム別
   バイナリを 11 個の `optionalDependencies` で配っているので、未対応の OS / CPU では
   **必須依存にしてもインストールは通り、実行時に落ちる**。§14 の「プリビルドが無い環境」は
   どちらにしても残る

したがって「実行してエラーが出たら追加インストールする」流れを正規の手順とし、
README とエラーメッセージの両方に書く。

- **ライブラリ本体は実行時依存ゼロのまま**（spec §3 判断 #2）。
  `src/` は `@napi-rs/canvas` を参照しない。シムは `bin/` にある
- ネットワークに触るのは `--google` / `--ttf <url>` / `--font`（同梱データの取得）。
  **`--offline` は 3 つすべてに適用する**

## 14. 決めたこと・残っていること

| 論点 | 決定 |
| --- | --- |
| プリビルドが無い OS / CPU | 動かない。**そう言う**（§13.2）。`--font` / `--input` は動く |
| リモートが変わったとき | キャッシュが実質の固定。**取得元の SHA-256 をヘッダに記録**して差分に出す（§4.4） |
| キャッシュの位置 | **ユーザのキャッシュディレクトリ**。`--cache-dir` で変更（§4.4） |

### プラットフォームの確認状況

CI の `rasterizer` ジョブ（`.github/workflows/ci.yml`）が毎回 5 つのランナーで
バインディングの読み込みと `--google` からの実生成、`--check` によるバイト一致まで通す。

| ランナー | プリビルド | 状態 |
| --- | --- | --- |
| `ubuntu-latest` | linux-x64-gnu | **確認済み** |
| `ubuntu-24.04-arm` | linux-arm64-gnu | **確認済み** |
| `macos-latest` | darwin-arm64 | **確認済み** |
