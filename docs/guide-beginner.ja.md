# はじめてのビットマップフォント — 初心者ガイド

「マイコンの画面に文字を出したい。フォントというものが要るらしいが、
仕組みがよく分からない」——そんな人のためのガイドです。
フォントの予備知識はいっさい仮定しません。

このライブラリのドキュメントは 3 部構成です。

| ガイド | 対象 |
| --- | --- |
| **このガイド** | フォントとは何かから知りたい人 |
| [用途別ガイド](./guide-usecases.ja.md) | やりたいことが決まっている人（レシピ集） |
| [上級者ガイド](./guide-advanced.ja.md) | 内部の仕組み・制約・拡張を知りたい人 |

正確な仕様は [仕様書](./spec.ja.md) にあります。

## 1. フォントとは何か

コンピュータの中で「あ」という文字は、**文字コード**（Unicode なら
U+3042 という番号。コードポイントと呼びます）でしかありません。
番号のままでは画面に出せないので、どこかで「番号 → 字の形」の変換が要ります。

**フォントとは、この対応表のことです。**

```
コードポイント（番号）        グリフ（字の形）
U+0041 'A'          ───→      ▲ の形をした画像や曲線
U+3042 'あ'         ───→      あ の形をした画像や曲線
```

字の形ひとつひとつを**グリフ**と呼びます。同じ「A」でも、ゴシック体と
明朝体ではグリフが違う——それが書体（typeface）の違いです。

## 2. アウトラインフォントとビットマップフォント

字の形の持ち方には大きく 2 通りあります。

- **アウトラインフォント**（TTF / OTF / WOFF）
  字の輪郭を曲線の式で持つ。どんなサイズにも滑らかに拡大できるが、
  表示するたびに「曲線 → ピクセル」の計算（ラスタライズ）が必要。
  PC やスマホのフォントはこれ。
- **ビットマップフォント**
  字の形を**ピクセルの点の並び**（小さな画像）としてあらかじめ持つ。
  表示は「点をそのまま置くだけ」なので計算がほぼ要らない。
  そのかわり、作ったサイズでしか綺麗に出ない。

マイコン（ESP32 や Arduino）でビットマップフォントが使われるのは、

1. ラスタライザを載せる ROM / RAM / CPU の余裕がない
2. 「どのピクセルが点くか」が完全に決まっていて、実機とシミュレータで
   1 ピクセルも違わない表示ができる

からです。このライブラリが扱うのはビットマップフォントです
（TTF は「ビットマップフォントの**材料**」として登場します。§7 参照）。

## 3. グリフの解剖 — 5 つの数字

ビットマップフォントのグリフは「小さな白黒画像」と「置き方を表す数字」の
組み合わせです。文字を並べるとき、ライブラリはペン先を左から右へ進めながら
グリフを置いていきます。

```
                 ペン位置（原点）はベースライン上にある
                 │
                 │← xOffset →│
                 │            ┌──────────┐ ─┬─ ここまでの距離が yOffset
                 │            │  ####    │  │   （ベースラインから上端。
                 │            │ #    #   │  │     上方向なので負の値）
                 │            │ #    #   │  │
                 │            │  ####    │  │
  ── ベースライン ┼────────────┼──────────┼─ ┴─────────────
                 │            │ #        │      ← 「g」や「p」はベースラインの
                 │            │#         │        下にはみ出す
                 │            └──────────┘
                 │←――――― xAdvance ―――――→│
                                          次の文字のペン位置
```

| 名前 | 意味 |
| --- | --- |
| `xOffset` | ペン位置から画像の左端までの距離 |
| `yOffset` | ベースラインから画像の上端までの距離（上に伸びるので普通は負） |
| `xAdvance` | この文字を描いたあと、ペンをどれだけ右へ進めるか（送り幅） |
| `bitmap.width / height` | 画像そのものの大きさ |

フォント全体にも数字があります。

| 名前 | 意味 |
| --- | --- |
| `ascent` | ベースラインから行の上端まで |
| `descent` | ベースラインから行の下端まで |
| `lineHeight` | 1 行分の高さ（次の行までの距離） |

「i」と「W」で幅が違うフォントを**プロポーショナル**、
全文字同じ幅のフォントを**等幅（モノスペース）**と呼びます。
違いは単に「グリフごとに xAdvance が違うか同じか」だけです。

### 白黒か、グレーか（1bpp と 8bpp）

- **1bpp**（1 bit per pixel）: 各ピクセルは点くか点かないかの 2 値。
  組込みフォントの大半はこれです。
- **8bpp**: 各ピクセルが 0〜255 の濃さを持ち、輪郭を滑らかに見せられます
  （アンチエイリアス）。VLW（TFT_eSPI の Smooth Font）などが使います。

## 4. 文字集合 — ビットマップフォント最大の現実問題

ビットマップフォントは 1 文字ずつ画像を持つので、
**収録する文字数がそのままデータサイズになります。**

実測例（このライブラリ同梱の 16px フォント）:

| 収録内容 | 文字数 | サイズ |
| --- | ---: | ---: |
| lgfxJapanMincho_16（JIS 第 2 水準までの日本語一式） | 4,425 字 | 約 163 KB |
| 同フォントから英数字と `:.` だけを抜き出したもの | 15 字 | 243 バイト |
| 時計表示用に `0-9` と `:` だけ | 11 字 | 188 バイト |

そこで組込みの世界では「**使う文字だけ入れる**」のが基本戦略になります。
時計なら数字と記号だけ、日本語 UI なら実際に表示する文言に出てくる漢字だけ、
という具合です。この「選んで入れる」操作を**サブセット化**と呼び、
このライブラリの主要機能のひとつです（[用途別ガイド §7](./guide-usecases.ja.md#7-文字を減らす足す)）。

逆に、入れ忘れた文字を表示しようとすると、四角い枠（俗に **tofu**）や
代替グリフが出ます。「出荷前に文言の文字が全部入っているか検査する」
機能もあります（`coverage`）。

## 5. フォント形式 — 同じ中身、違う包み紙

ビットマップフォントのファイル形式はライブラリごとにバラバラです。
中身（グリフ画像と数字）はどれも §3 で説明したものなのに、
バイト列への詰め方が違うだけで互換性がありません。

| 形式 | 主な使い手 | 特徴 |
| --- | --- | --- |
| **u8g2** | u8g2 / LovyanGFX | RLE 圧縮つきで小さい。1bpp |
| **GFXfont** | Adafruit GFX / LovyanGFX | C のヘッダとして配られる定番。1bpp |
| **BDF** | X11 / 各種ツール | テキスト形式で人間が読める。交換用 |
| **VLW** | Processing / TFT_eSPI | 8bpp アンチエイリアス（Smooth Font） |
| **BFF** | LVGL (lv_font_conv) / LovyanGFX | 1〜4bpp、カーニング対応 |
| **FONTX2** | 日本の古い機器・自作機界隈 | Shift_JIS ベースの日本語形式 |
| **C ソース** | Arduino 全般 | 上記を `.h` ファイルに埋め込んだもの |

このライブラリは、これら全部を読み込んで**中立モデル**という共通の形
（§3 の構造そのもの）に揃えます。中立モデルからは任意の形式に書き出せる
ので、「u8g2 → GFXfont」のような変換は「読む → 書く」の 2 手で済みます。

## 6. まず触ってみる

### ブラウザで（インストール不要）

[Web Viewer](https://tanakamasayuki.github.io/LGFXFontToolJs/) を開くと、
LovyanGFX に内蔵されている全 186 フォントを一覧・プレビューできます。
手元のフォントファイルを開いて中身を覗くこともできます。

### Node.js で（10 行）

```sh
npm install lgfx-font-tool
```

```js
import { loadFont, createBitmap, drawString, textWidth, fontHeight, bitmapToText }
  from 'lgfx-font-tool';

const font = await loadFont('lgfxJapanGothic_16');   // 同梱コレクションから
const bmp = createBitmap(textWidth(font, 'あ'), fontHeight(font), 1);
drawString(bmp, font, 'あ', 0, 0);
console.log(bitmapToText(bmp));
```

実行すると、フォントに入っている「あ」がそのまま見えます:

```
......#.........
......#.........
......#####.....
..######........
.....##..#......
.....#######....
.....##.##.##...
...###..#....#..
...#.#.##....#..
..#..###.....#..
..#..##......#..
..#..##.....#...
..###.#.####....
```

この `bmp` の中身（バイト列）は、そのままマイコンに送って表示できる
ビットマップです。しかもこのライブラリの描画は、実物の LovyanGFX が
描く結果と**ピクセル単位で完全一致**することがテストで保証されています。
つまり PC 上で見たものが、そのまま実機に出ます。

> 同梱コレクションのうち日本語・中国語などの大きいフォント（合計 42MB）は
> npm パッケージには入っておらず、初回の `loadFont` 時に GitHub Pages から
> 自動ダウンロードされます。オフラインで使う方法は
> [上級者ガイド §5](./guide-advanced.ja.md#5-フォントデータの配布とオフライン利用) を参照。

## 7. 新しいフォントを作るには

手書き……ではなく、**アウトラインフォント（TTF）を材料にして焼き付けます**。
「この TTF を、このサイズで、この文字だけ」と指定すると、TTF をラスタライズ
してビットマップフォントを生成できます。ブラウザで動く
[Generator](https://tanakamasayuki.github.io/LGFXFontToolJs/generator.html)
を使えばコードなしで作れます（Google Fonts の再配布可能な書体も選べます）。

## 8. 用語集

| 用語 | 意味 |
| --- | --- |
| コードポイント | Unicode 上の文字番号（U+3042 など） |
| グリフ | 1 文字分の字形データ |
| ベースライン | 文字が乗る基準線。「g」の丸い部分の下端あたり |
| メトリクス | xOffset / xAdvance / ascent などの寸法情報の総称 |
| 送り幅（advance） | 1 文字描いたあとペンが進む距離 |
| サブセット化 | 使う文字だけを残してフォントを小さくすること |
| tofu | 未収録文字の代わりに出る四角 □ |
| 1bpp / 8bpp | ピクセルあたりのビット数。2 値かグレースケールか |
| ラスタライズ | アウトライン（曲線）をピクセルに変換すること |
| 中立モデル | このライブラリ内部の共通フォント表現 |
