# Changelog / 変更履歴

## Unreleased
- (EN) **The command is now `lgfx-font-tool`, matching the package name; `lgfx-font` is gone.** npx resolves its first argument against the registry, so a command named differently from its package forced the two-part `npx -p lgfx-font-tool lgfx-font build …` on every reader, and a bare `npx lgfx-font` 404s (no such package — and if someone publishes one later, that typo would run a stranger's code). One name for the package, the binary and the npx argument removes all of it: `npx lgfx-font-tool build …`. The `Rebuild with` line, `--help`, error messages, the READMEs and §3 of the CLI reference follow, and §3 no longer has to explain why `-p` was needed.
- (JA) **コマンド名をパッケージ名と同じ `lgfx-font-tool` にした。`lgfx-font` は廃止。** npx は最初の引数をレジストリに問い合わせるので、パッケージ名と違う名前のコマンドは読む側に常に `npx -p lgfx-font-tool lgfx-font build …` の 2 段書きを強いていた。素の `npx lgfx-font` は 404 になる（そんなパッケージは無い。将来誰かが取れば、その打ち間違いが他人のコードを動かすことにもなる）。パッケージ・バイナリ・npx の引数を 1 つの名前に揃えればすべて消えて、`npx lgfx-font-tool build …` で済む。`Rebuild with` の行、`--help`、エラーメッセージ、README、CLI 仕様書 §3 も揃えた。§3 から「なぜ `-p` が要るのか」の説明は不要になった。
- (EN) **CLI: the `Rebuild with` line records `--out` again, as a bare file name.** 2.2.2 dropped it whole, which was one step too far: it left the reader to supply the one thing the file already knows — what it is called — and `--name`, derived from that same name, was recorded anyway. Recording the file name and never the directory keeps what 2.2.2 was protecting: a path is what made one font written to four directories into four different files, and a bare name does not vary with where the command ran. It also adds no variation that was not already there, since `--name` defaults to the file name. An absolute path, a relative one, `../../elsewhere/font.h` — all come out as `font.h`, and the line now runs as it stands, landing the file wherever you run it. The heading is plain `Rebuild with:` again.
- (JA) **CLI: `Rebuild with` の行に `--out` を再び載せる。ただしファイル名だけ。** 2.2.2 で丸ごと落としたのは行き過ぎだった。そのファイル自身が知っている「自分の名前」を読む側に書かせることになり、しかも同じ名前から導かれる `--name` は結局載っていた。ファイル名だけを載せてディレクトリを載せなければ、2.2.2 が守ろうとしたものは守られる。同じフォントを 4 つのディレクトリに置いて 4 つとも中身が違う、を起こしていたのはパスであって、名前だけなら実行場所で変わらない。`--name` の既定値がファイル名である以上、ぶれも増えない。絶対パスでも相対パスでも `../../elsewhere/font.h` でも出るのは `font.h` だけで、行はそのまま回り、回した場所にファイルが出来る。見出しも `Rebuild with:` に戻した。
- (EN) CLI: in a `--preview` glyph sheet, **cells past the last glyph are now hatched**. The sheet is 16 cells per row, so the last row is usually part empty, and a blank cell read exactly like a glyph that draws nothing — a space — leaving no way to tell "this character arrived and is blank" from "there is nothing here". Diagonals rather than a flat tone, so the difference survives a quick look and a screen that adjusts levels.
- (JA) CLI: `--preview` のグリフ一覧で、**最後のグリフより後ろのセルに斜線を引くようにした**。1 行 16 セルなので最終行はたいてい途中までで、空白のセルは「何も描かないグリフ」＝スペースと全く同じに見えていた。つまり「その文字は入っていて空白」なのか「そこには何も無い」のかが区別できなかった。平坦な網掛けではなく斜線にしたのは、ざっと見たときにも、階調を自動調整する画面でも違いが残るように。
- (EN) Docs: the READMEs now read in the order there is least to install — web apps, then the command line, then the library. `npm install lgfx-font-tool` was above the CLI section, where a reader after the CLI would copy it and get 33 MB of rasterizer plus a local copy that then **shadows `npx`** (§3, first two rows); it now sits under "As a library", which is the only place it is needed. The TTF rasterizer's 24 lines are a sentence and a link, since §13.2 of the CLI reference already covers it, and the CI example names a version so a later release cannot fail `--check` by changing the shape of the output.
- (JA) ドキュメント: README を「インストールが要らないものから順」に並べ替えた（Web アプリ → コマンドライン → ライブラリ）。`npm install lgfx-font-tool` が CLI 節より上にあり、CLI が目的の読者がそれを実行すると 33 MB のラスタライザと、**`npx` を上書きするローカル版**（§3 の上 2 行）を手に入れてしまっていた。必要なのはライブラリ利用時だけなので「ライブラリとして使う」節に移した。TTF ラスタライザの 24 行は CLI 仕様書 §13.2 に既にあるので 1 文とリンクに減らし、CI の例は版を明示して、後のリリースで出力の形が変わって `--check` が落ちないようにした。
- (EN) Docs: §3 of the CLI reference now records what each `npx` spelling actually does, measured on npm 10.9.4. A bare name runs whatever is already there and says nothing when a newer release exists; `@latest` re-resolves, and the install it then needs is what asks `Ok to proceed?`; `@<version>` runs from the cache with no lookup and no question. **CI needs no `--yes`** — npm asks only when stdin is a TTY and `ci-info` does not recognize a CI, and GitHub Actions is recognized. The claim that naming a version cannot get past a globally installed copy was an artefact of the old two-part `npx -p … <command>` form, where the command name reached `PATH` on its own; with one word the version is part of what npx looks up, so no binary matches it.
- (JA) ドキュメント: CLI 仕様書 §3 に、`npx` の書き方ごとの実挙動を npm 10.9.4 での実測として書いた。素の名前は既にあるものを動かし、新しい版が出ていても何も言わない。`@latest` は引き直し、そのとき必要になるインストールが `Ok to proceed?` を出す。`@<版>` は問い合わせも確認もなくキャッシュから動く。**CI に `--yes` は要らない**（npm が聞くのは stdin が TTY で、かつ `ci-info` が CI と判定できなかったときだけで、GitHub Actions は判定される）。「版を書いてもグローバル版に勝てない」という記述は、コマンド名がそのまま `PATH` に届く旧来の `npx -p … <コマンド>` の形に固有の話だった。1 語になった今は版も引く文字列の一部なので、それに一致するバイナリは無い。
- (EN) CI: `scripts/check-coverage.mjs` was failing on every platform. It looked for the literal `Rebuild with:`, but 2.2.2 changed that heading to `Rebuild with (add --out for wherever this file goes):`, so the check had been asserting against a string the tool no longer writes. It now matches the recorded command itself — the part that carries the meaning — rather than the prose around it.
- (JA) CI: `scripts/check-coverage.mjs` が全プラットフォームで落ちていた。`Rebuild with:` という文字列を探していたが、2.2.2 でこの見出しは `Rebuild with (add --out for wherever this file goes):` に変わっており、ツールがもう書かない文字列を検査し続けていた。見出しの文言ではなく、意味を持つ部分である記録されたコマンド自体を検査するようにした。

## 2.3.0
- (EN) **Packaging fix: the package depended on itself.** `dependencies` carried `lgfx-font-tool: ^2.2.1`, shipped that way in 2.2.2, so installing it pulled a nested older copy of itself. Inside a checkout it was worse: `node_modules/.bin/lgfx-font` pointed at the published copy, so `npx lgfx-font` in this repository ran the release rather than the working tree. Removed, and `scripts/check-releasable.js` now refuses to release a package that lists its own name in any dependency field — one stray `npm i <own name>` is all it takes to bring it back.
- (JA) **梱包の修正: パッケージが自分自身に依存していた。** `dependencies` に `lgfx-font-tool: ^2.2.1` が入ったまま 2.2.2 として公開されていて、インストールすると入れ子で古い自分も落ちてきていた。リポジトリ内ではさらに悪く、`node_modules/.bin/lgfx-font` が公開版を指すため、ここで `npx lgfx-font` を叩くと作業ツリーではなく公開版が動いていた。削除し、`scripts/check-releasable.js` が「依存欄に自分の名前がある状態ではリリースさせない」ようにした。`npm i <自分>` を一度打つだけで戻るため。
- (EN) CLI: new `--pin-version`, which records the tool's version in the `Rebuild with` line (`npx -p lgfx-font-tool@2.2.2 lgfx-font build …`). Without it npx resolves the latest, so a rebuild can pick up a release that changes the shape of the output; with it that cannot happen, but every upgrade of the tool then rewrites every generated header. Which cost is worth paying is the project's call, so it is off by default. The flag records itself, so rerunning the recorded command reproduces the same header.
- (JA) CLI: `--pin-version` を追加した。`Rebuild with` の行にツールの版を書き込む（`npx -p lgfx-font-tool@2.2.2 lgfx-font build …`）。書かないと npx が最新を解決するので、出力の形が変わる版が出ていれば作り直しの結果が変わる。書けばそれは起きないが、代わりにツールを上げるたび全ヘッダが書き換わる。どちらの費用を払うかはプロジェクト次第なので既定は off。フラグは自分自身も記録するので、書かれたコマンドをそのまま回せば同じヘッダになる。
- (EN) Docs: §3 of the CLI reference now explains why `npx` does not give the same answer twice on one machine, and that **naming a version does not make it deterministic** — a command of the same name on `PATH` wins (a globally installed 2.2.0 ran even for `npx -p lgfx-font-tool@2.2.2`), a `node_modules` at or above the cwd wins next, and only then does the npx cache apply, which is keyed by the spec string and never re-resolved. Both of the first two ignore `-p` entirely. The section now says to install the package and use `npm ci` when it has to be certain, and lists the commands that show what actually ran.
- (JA) ドキュメント: CLI 仕様書 §3 に、同じマシンでも `npx` の結果が一定しない理由と、**版を書いても決定的にはならない**ことを書いた。PATH に同名のコマンドがあればそれが勝ち（グローバルの 2.2.0 が `npx -p lgfx-font-tool@2.2.2` でも動いた）、次に cwd から上の `node_modules` が勝ち、npx のキャッシュはその後にしか効かない。前の 2 つは `-p` を完全に無視する。確実にしたいならインストールして `npm ci` を使うこと、実際に何が走ったかを確かめるコマンドも載せた。

## 2.2.2
- (EN) CLI: the `Rebuild with` line no longer records `--out`. Where a file was written is not part of what it contains, and recording it turned one font placed in four directories into four different files — which defeats copying a generated header around, and strays from the format spec's "same input, same bytes" (the input being the character set, yAdvance, and target ABI). The comment now reads `Rebuild with (add --out for wherever this file goes)`, and `--name` is always recorded, resolved, so the one thing left to supply is the path you are already looking at. Reported by a user with the same clock font in four places and four different files.
- (JA) CLI: `Rebuild with` の行に `--out` を載せないようにした。ファイルをどこに書いたかはファイルの中身ではなく、載せると同じフォントを 4 つのディレクトリに置いただけで 4 つとも中身の違うファイルになる。生成済みヘッダをコピーして使い回せず、形式仕様の「同じ入力なら同じバイト列」（入力＝文字集合・yAdvance・対象 ABI）からも外れていた。見出しを `Rebuild with (add --out for wherever this file goes)` に変え、`--name` は指定が無くても正準化後の実際の識別子を必ず載せるようにしたので、書き足すのは今見ているパス 1 か所だけになる。同じ時計フォントを 4 か所に置いて 4 ファイルとも別物になった、という報告を受けての修正。
- (EN) CLI: the `Rebuild with` line, and every example in the READMEs and the CLI reference, now use `npx -p lgfx-font-tool lgfx-font` instead of a bare `npx lgfx-font`. There is no package called `lgfx-font` (`npm view lgfx-font` is a 404), so the short form works only where npm resolves the command name to a package or where it is already in `node_modules`, and 404s elsewhere. §3 explains this and notes that an installed copy needs no `npx` at all.
- (JA) CLI: `Rebuild with` の行と、README・CLI 仕様書のすべての例を、素の `npx lgfx-font` から `npx -p lgfx-font-tool lgfx-font` に変えた。`lgfx-font` というパッケージは存在せず（`npm view lgfx-font` は 404）、素の形は npm がコマンド名からパッケージを引けた環境か、`node_modules` に既に入っている場合しか動かない。§3 にその理由と、インストール済みなら `npx` ごと不要であることを書いた。
- (EN) The `Line box` line in a generated header now says the numbers are the typeface's, for line spacing. A CellFont reader also sees a per-cell `yOffset`, and the two are different quantities (spec §4 defines the cell's `ascent = -yOffset`); the label keeps them from being read as one.
- (JA) 生成ヘッダの `Line box` の行に、その数値が書体のメトリクスで行送り用であることを明記した。CellFont ではセルごとの `yOffset` も目に入り、この 2 つは別の量である（仕様 §4 はセルの `ascent = -yOffset` と定める）。混同されないように但し書きを付けた。

## 2.2.1
- (EN) CLI: the `Rebuild with` line always quotes a `--chars` value, even a single character. `--chars ℃` needs no quoting to run, but without quotes it reads as if one went missing, and the value is text rather than an identifier — the quotes show where it ends. A value starting with `-` and an empty value are quoted whatever they contain, since they would otherwise be read back as a flag or disappear.
- (JA) CLI: `Rebuild with` の行で、`--chars` の値を 1 文字でも必ず引用するようにした。`--chars ℃` はシェル的には引用が要らないが、引用が無いと片方が消えたように読める。識別子ではなく内容を表す指定なので、どこまでが値かを引用で示す。先頭が `-` の値と空文字は、読み戻すとフラグになったり消えたりするので中身に関わらず引用する。
- (EN) CLI: the `Rebuild with` line reduces any path pointing outside the working directory to its file name, not just paths written absolutely. A relative `../../elsewhere/font.ttf` used to be recorded verbatim, which leaked the layout above the project the absolute form was already protected from. The decision is now made after resolving, and separators and a leading `./` are normalized so two spellings of one path give the same line. Paths inside the working directory are still kept: those are what rebuilding needs.
- (JA) CLI: `Rebuild with` の行が、作業ディレクトリの外を指すパスを、絶対パスで書かれたものだけでなくすべてファイル名に丸めるようにした。`../../どこか/font.ttf` のような相対パスはそのまま記録されていて、絶対パスでは守られていたはずのプロジェクト外の構成が漏れていた。判断を解決後に行うようにし、区切り文字と先頭の `./` も正規化したので、同じ場所を指す別の書き方が同じ 1 行になる。作業ディレクトリの中のパスは従来どおり残す。作り直しに必要な情報だから。

## 2.1.0
- (EN) CI's `rasterizer` job now also runs `scripts/check-coverage.mjs` on all five runners: it asks a typeface for a character it does not have, requires that to fail rather than silently substitute, then fills it from a second typeface and checks both are credited. Presence detection depends on the host's installed fonts, so this is a per-platform fact a unit test cannot establish.
- (JA) CI の `rasterizer` ジョブが 5 ランナーで `scripts/check-coverage.mjs` も回すようにした。書体が持たない文字を要求して、黙って代替されずに失敗することを確かめ、次に別の書体から補完して両方が権利表記に載ることを確かめる。収録判定はホストに入っているフォントに依存するため、単体テストでは押さえられないプラットフォーム別の事実である。
- (EN) **CLI bug fix: presence detection.** Skia's font registry has no equivalent of a browser `FontFace`'s `unicode-range`, so it silently substituted a system font for any character the requested typeface lacks — asking DejaVu Sans, which has no kanji, for `温` produced a 152 px glyph drawn by whatever the host had installed. Every character therefore looked present: `missing` was under-reported, `--allow-missing` never fired, and the output depended on the machine's installed fonts. The CLI now reads the font file's own `cmap` (`bin/coverage.js`, formats 0/4/6/12) and rasterizes only what the typeface actually contains. Isolating the registry was tried first and is strictly worse (measured). The browser path was always correct and is unchanged, as is format spec §2.3 — this lives entirely in `bin/`. A compressed WOFF / WOFF2 cannot be read this way; that case warns and proceeds unfiltered.
- (JA) **CLI の不具合修正: 収録判定。** Skia のフォント登録にはブラウザの `FontFace` の `unicode-range` に相当する仕組みが無く、対象書体が持たない文字を黙ってシステムフォントで代替描画していた。漢字を持たない DejaVu Sans に `温` を要求すると、環境に入っている別のフォントが 152 px の字形を返す。結果としてすべての文字が「収録あり」に見え、`missing` が実際より少なく報告され、`--allow-missing` は発火せず、出力がそのマシンに入っているフォントに依存していた。CLI がフォントファイルの `cmap` を自分で読むようにし（`bin/coverage.js`、書式 0/4/6/12）、その書体が実際に持つ文字だけをラスタライズする。登録の隔離も試したが実測で悪化するため採らなかった。ブラウザ側は元から正しく、変更していない。形式仕様 §2.3 もそのままで、この処理は `bin/` に閉じている。圧縮された WOFF / WOFF2 は `cmap` を読めないため、警告を出して絞り込みなしで通す。
- (EN) CLI: new `--fallback <spec>`, repeatable, tried in order — characters the source lacks are taken from another typeface, the same feature the Web UI already had. The notation matches the source (`google:<family>`, a path, or a URL). Each contributing typeface gets its own attribution block in the output, since a fallback is a source of the derived work too.
- (JA) CLI: `--fallback <spec>` を追加（繰り返し可・指定順に試行）。書体に無い文字を別の書体から埋める。Web UI に既にあった補完を CLI にも入れたもの。記法は入力元と同じ（`google:<family>` / パス / URL）。埋めた書体も派生元なので、書体ごとに権利表記のブロックを出力に入れる。
- (EN) `--fallback` also works with `--font` / `--input`, which is how characters get added to a bitmap font you already have. There is deliberately no "concatenate two fonts" feature: filling in what is missing needs fewer concepts and yields one font. When the metrics disagree the base font's line box is kept and both sets of numbers are printed, since silently rescaling would be worse. For a font this tool made, the better route is the `Rebuild with` command from its own header plus the extra characters — every glyph then comes from one typeface at one `--em`. A CellFont header cannot be read back (C source input reads GFXfont and u8g2), and the error now says so and what to do instead.
- (JA) `--fallback` は `--font` / `--input` にも効く。手元のビットマップフォントに文字を足す道はこれ。「フォント同士を連結する」機能は意図的に持たない。足りない字を補うほうが概念が少なく、出力も 1 個で済む。寸法が食い違う場合は入力フォントの行高を保ち、両方の値を表示する（黙って拡縮するほうが悪い）。本ツールで作ったフォントなら、ヘッダの `Rebuild with` のコマンドに文字を足して回すほうがよい。全字形が同じ書体・同じ `--em` から出るため。CellFont ヘッダは読み戻せない（C ソース入力が読むのは GFXfont と u8g2）ので、その旨と代わりの手順をエラーで案内する。
- (EN) CLI: generated C source now records the command that produced it, as a `Rebuild with:` line in the header comment. Flags that do not affect the file are left out and the order is fixed, so the line stays canonical; an absolute path outside the working directory is reduced to its file name, so no home directory layout leaks in. It is one line however long — a trailing-backslash wrap reads better but its continuation lines are still inside the `//` comment, so copying the block hands the shell nothing but comments — and it is prefixed with `npx`, which runs whether or not the package is installed globally. **This changes the bytes of every CLI-generated header**, so a `--check` in CI will report a mismatch until the output is regenerated. Web UI output is unaffected.
- (JA) CLI: 生成した C ソースの先頭コメントに、そのファイルを作ったコマンドを `Rebuild with:` として記録する。出力に影響しない指定は載せず、並び順は固定なので正準出力を壊さない。作業ディレクトリ外の絶対パスはファイル名だけに丸めるので、ホームディレクトリの構成が混ざらない。どれだけ長くても 1 行で出す（`\` で折り返すと読みやすいが、続きの行も `//` の中なのでコピーするとシェルにはコメントしか渡らない）。`npx` を付けるのは、グローバルに入れていなくてもそのまま動くから。**CLI 生成ヘッダのバイト列が変わる**ため、CI の `--check` は出力を作り直すまで不一致を報告する。Web UI の出力は変わらない。
- (EN) CLI: new `--no-wrapper` for `--format u8g2`, which leaves out the `lgfx::U8g2font` declaration and names the byte array itself the font symbol — the shape upstream u8g2 fonts have, usable with `u8g2.setFont()` and no LovyanGFX. Only that one line was ever LovyanGFX-specific; the data is upstream u8g2's own format. Passing it with another format is an argument error, since what the others declare is required by the format itself. (`vlw` / `bff` already emitted the array alone.)
